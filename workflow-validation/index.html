    Validate workflows

    Use these checks to validate an Agentmux build and the workflow features you intend to use. Model-free checks exercise process control, private Git storage, verification and recovery without loading provider credentials.

    Build and regression checks

    Run from a source checkout with Go 1.24 or newer, Python 3, Git and Node.js. Terminal integration tests also require tmux.

    make build
go test -race -count=1 -timeout=20m ./...
go vet ./...
node cmd/agentmux/workweb/app.test.cjs
python3 scripts/test-validate-workflows.py
python3 scripts/test-soak-workflows.py
python3 scripts/test-workflow-review-evidence.py

    Conditional integrations report skips when their prerequisites are absent. A passing default suite does not establish that those integrations ran. When testing a binary outside bin/amx, set both AGENTMUX_TEST_BINARY (terminal journeys) and AGENTMUX_INTEGRATION_BINARY (workflow/report integrations) to its absolute path. Otherwise terminal journeys use the checkout's last built binary.

    Observation and reporting

    The v0.15.0 source includes model-free regressions for owner observation, task progress and native readiness:

    go test -race ./internal/managed -run 'TestObservation|TestTaskProgress|TestNativeReadiness|TestOperationalRead|TestNativeSummary' -count=1
go test -race ./cmd/agentmux -run 'TestObserve|TestNativeObservation' -count=1
node --test cmd/agentmux/workweb/app.test.cjs
python3 scripts/test-summarize-observations.py
AGENTMUX_INTEGRATION_BINARY="$PWD/bin/amx" python3 scripts/test-summarize-observations.py
python3 scripts/test-summarize-comparison.py

    These check bounded full-history summaries, exact attempt/credential fences, separate event and worker timestamps, restart-unknown progress, unavailable components and read-only inspection. Operational-read controls keep a blocked diagnostic connection outside the unchanged 500 ms lease monitor and verify one-slot admission, read-only SQL, shutdown cancellation and credential rotation. Native-summary controls cover unknown admission, authorization and pagination. Structured-diagnostic controls distinguish credential, authorization, local timeout/cancellation, transport, protocol and storage failures without guessing from prose. They check acquisition/decoding durations and explicit null timing for unattempted native reads; existing completion and human output stay intact. The offline reporter rejects malformed, mixed-state and oversized captures, omits injected private fields and keeps legacy/missing timings unknown. Its memory and episode bounds do not grow with capture length. Setting AGENTMUX_INTEGRATION_BINARY runs a real command-only managed workspace through live, completed and stopped-broker captures, checks source/task preservation and offline-report privacy, and confirms shutdown of that exact fixture runtime. Without the variable, that integration reports a skip; the other reporter controls still run. Comparison-summary controls additionally exercise the actual deterministic actor/check failure harness and contradictory records. They make no model calls. They do not prove provider acceptance, useful model progress or elapsed production use. See observability for operational commands and interpretation.

    Exact initial approval and final acceptance

    Guided work in v0.14.0 declares review_policy: early-approval-v1. Its clean path runs an implementation, independent checks and a fresh read-only review. Only an untruncated approval of that exact checked revision can mark address-review and final-review as skipped. Their retained evidence records the skip reason and zero execution attempts. The original approval is retained; it is not replaced by a fabricated final review. final-check always executes the configured acceptance commands against the final revision.

    go test -race ./internal/workflow -run 'TestEarlyApproval' -count=1
python3 scripts/test-workflow-review-evidence.py

    The minimum clean path uses two native CLI turns; retries can increase that count. Requested changes retain the coder response and fresh final review. Legacy plans with no review policy retain their full loop. Controls reject missing/forged approval identity, changed dependencies, synthetic execution or usage evidence, stale source/results, altered checked revisions, invalid reviews and failed or canceled final checks. Readiness for application still requires fresh passing evidence, and application remains explicit. These command-only controls do not measure model quality or prove a native-provider speedup.

    Model-free workflow journeys

    Choose a new output directory for each run. The validator creates disposable repositories and checks source preservation, durable reports, verification and explicit application behavior.

    validation_root=$(mktemp -d)
python3 scripts/validate-workflows.py --binary bin/amx --output "$validation_root/flow"
python3 scripts/validate-workflows.py --binary bin/amx --output "$validation_root/work" --guided

    Inspect validation.json: its completion state and case results are the run authority. diagnostic.json describes case progress and is not a substitute for successful finalization. An interrupted process or missing final record does not establish success.

    Use --storage shared only to check explicit legacy compatibility. New workflows should use the default private stores.

    Required Linux isolation

    Full workflow isolation requires Linux, Bubblewrap with capped tmpfs support, and working user/PID namespaces. Requested isolation fails closed when the host cannot provide it. Process-group tests alone do not validate filesystem or network isolation.

    make test-sandbox

isolation_root=$(mktemp -d)
python3 scripts/validate-workflows.py --binary bin/amx --output "$isolation_root/flow" \
  --storage private --isolation bubblewrap --containment pid-namespace
python3 scripts/validate-workflows.py --binary bin/amx --output "$isolation_root/work" \
  --guided --storage private --isolation bubblewrap --containment pid-namespace

    The workflow oracle and cleanup regressions also have an explicit real-CLI isolation mode. A private evidence parent retains integration records for every outcome:

    evidence_root=$(mktemp -d)
AGENTMUX_SANDBOX_INTEGRATION=1 \
AGENTMUX_INTEGRATION_BINARY="$PWD/bin/amx" \
AGENTMUX_WORKFLOW_TEST_EVIDENCE_ROOT="$evidence_root" \
  python3 scripts/test-soak-workflows.py

    Keep evidence private: it can contain repository contents, patches, task instructions and process details. Review artifacts before sharing them.

    Fault and recovery soak

    The model-free soak checks interrupted turns, verification failures, uncertain application and recovery, source/staging preservation, cleanup and evidence publication. By default each iteration exercises every scenario class.

    soak_root=$(mktemp -d)
python3 scripts/soak-workflows.py --binary bin/amx --output "$soak_root/run" \
  --iterations 10 --duration-seconds 1800 \
  --storage private --isolation bubblewrap --containment pid-namespace

    Inspect soak.json for state, completed, iteration counts, assertions and coverage exclusions. A selected scenario subset validates only that subset. Cleanup observations cover the recorded process trees. Worker containment also depends on the required namespaces; unrelated host services remain outside that boundary.

    Live provider checks

    Provider tests require an explicit profile, selected authentication, a disposable repository and bounded execution. Review the validator's --help before using --native or a native comparison: these options can make billable requests. Run only the provider routes you have configured and intend to use.

    Recorded protocol fixtures establish parser behavior for those frames. Native CLI startup establishes startup behavior. An actual verified tool task supplies stronger evidence for that profile, version and task; none guarantees future provider compatibility or arbitrary task correctness.

    See provider compatibility, guided coding, and advanced workflows for setup.

    Interpret the boundaries

    • The Go controller and any selected host inference adapter remain trusted.
    • Private Git stores isolate run evidence; explicit shared storage retains legacy source-store behavior.
    • Bubblewrap constrains selected workers and checks. Independent host writers and services remain outside its authority.
    • Selection bounds are not a hard workspace disk quota. Native deadlines and admission limits do not guarantee a monetary cap; use provider-side controls.
    • Recovery resolves existing application evidence. It does not replay a patch or infer a missing outcome.
    • Exact revision checks and fresh reviews provide task-specific evidence. They do not prove universal correctness.

    Use the security model and hardening guide when selecting the boundaries for a deployment.
